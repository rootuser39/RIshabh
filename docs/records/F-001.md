# F-001 — motion preference stopped at the image boundary

- System: Void Observatory
- Recorded: 2026-10-02
- State: RESOLVED
- Environment: local headless Chromium 153.0.8010.0

## Symptom

The animated SVG remained visually different across two captures after the host
page's reduced-motion preference was changed. Opening the SVG directly produced
zero active animations under reduced motion, but this did not establish the same
behavior for an SVG embedded as an image. Reloading the host and selecting a new
image URL did not resolve the observed behavior in that verification session.

## Initial hypothesis

The SVG's own `prefers-reduced-motion` media query would be sufficient in both
contexts.

## Root cause boundary

The observation is a media-preference propagation inconsistency in the embedded
image context. The browser's internal cause was not established. This record
does not claim that every browser or every Chromium build behaves this way.

## Fix

Generate explicit animation-free SVGs, then use the host `<picture>` element to
select them for reduced-motion settings. Select the same assets when the visitor
uses Pause motion. Inline companion animation is stopped in the host stylesheet.

## Verification

The local image-level regression check selected the still source and produced
identical image captures across the comparison interval. Normal motion produced
different captures. The new browser suite repeats that check and also verifies
that all artwork sources switch under the preference. The static SVGs contain no
animation declarations or keyframes.

## Lesson

Test accessibility behavior in the embedding context that visitors actually use.
A correctly behaving standalone asset is insufficient evidence for an embedded
one.
