# Maintaining the Void Observatory

The README and interactive interface share the same records. Edit content rather
than redesigning a panel. The site uses Python's standard library at build time
and plain HTML, CSS and JavaScript in the browser.

## Run the interface

From the repository root, with Python 3.12 or newer:

```sh
python scripts/build_observatory.py
python scripts/build_lab.py
python -m http.server 8080
```

Open `http://localhost:8080/`. The generated `index.html` is also suitable for
any ordinary static host. Use the server for local checks so the page's content
security policy and local asset URLs have the same origin behavior as deployment.

## Update the working record

1. Edit `content/current-signal.json` and its `updated` date when the signal changes.
2. Add a record to the relevant collection, using a unique ID.
3. Include a source revision, evidence type and known limits. Only record numbers
   that belong to an actual source or run, with units.
4. Run `python scripts/build_lab.py`, then `python scripts/build_lab.py --check`.
5. Commit the content and generated README/interface together.

Files:

- `site.json`: identity, operating principles and collaboration protocol.
- `current-signal.json`: manually maintained work snapshot and last shipped item.
- `systems.json`: questions, implementation, architectural scope and evidence links.
- `experiments.json`: commands, observations, metrics, hypotheses and next tests.
- `field-logs.json`: concise observations and source reviews.
- `failures.json`: symptom → hypothesis → evidence → fix → lesson.
- `questions.json`: editable architectural questions and their basis.
- `tools.json`: roles, connected systems and evidence boundaries.
- `depth.json`: documented exploration states, not skill scores.
- `transmissions.json`: actual notes and writing. An unknown date stays null.
- `map.json`: architectural scope, shared questions and layer placement.
- `sources.json`: public source revisions reviewed for the snapshot.
- `derived.json`: generated counts; do not edit this file manually.

## Adding a record

Copy an existing record's shape. IDs link experiments, field notes and failures.
An empty collection `[]` renders an explicit empty state. A new system may omit
`asset`; it receives a text overview instead of requiring new artwork.

For an experiment, use `synthetic`, `measured` or `planned`. A planned experiment
must not contain measurements. Metrics require `label`, `value` and `unit`, plus
record-level source provenance. A null completion value means not completed in
the current synthetic model; it is not converted to zero or a successful run.
Do not use fake measurements as layout filler.

Failure states: `OPEN`, `INVESTIGATING`, `UNDERSTOOD`, `RESOLVED`.
Exploration states: `UNEXPLORED`, `ORIENTING`, `ACTIVE`, `OPERATIONAL`, `BUILT WITH`.
These describe records, not expertise. CORTEX retains only the already-public
architecture summary; private implementation details are not published here.

## Verify changes

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/build_lab.py --check
node --check interface/lab.js
```

The optional browser suite needs Playwright and an installed Chromium browser:

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser.cjs
```

It starts its own local server and checks widths, disclosures, filters, motion,
keyboard focus, the terminal, content security policy and the no-JavaScript view.
Browser tooling is a verification dependency; the website has no npm runtime.

## Publish with GitHub Pages

Pages was not enabled at the inspection snapshot. The connected GitHub tools
cannot change that repository setting. No hosted URL is claimed before deployment.

Enable Pages once in
[repository Pages settings](https://github.com/rootuser39/RIshabh/settings/pages):
set **Source** to **GitHub Actions**. Then run **Verify and publish laboratory**
from the Actions tab, or push a relevant change. Its Pages deployment job only
runs after repository metadata reports that Pages is enabled. The workflow uses
the standard Pages and OIDC permissions; no personal token or secret is needed.

The site URL will normally be `https://rootuser39.github.io/RIshabh/`. Treat it as
an expected URL until the deployment actually succeeds. Set `site.hosting.enabled`
and `site.hosting.url` after verification to publish a direct link in the README.

For another static host:

```sh
python scripts/build_lab.py --package _site
```

Serve `_site/`. The package contains local SVGs, not the preserved 2.6 MB historical
PNG. Content and links remain usable with no runtime GitHub API, analytics or
external font/image services. Motion preference is stored locally only when the
visitor chooses Pause/Resume motion.
